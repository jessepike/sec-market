# Lessons

Working lessons for agents on this project, newest first, at most about 15. Each line carries a tag:

- `[new:<date>]` recorded this session, not yet reviewed for the owner's shared knowledge base;
- `[withheld:<date>]` reviewed and kept here because it is specific to this project.

The owner keeps a shared knowledge base of lessons across projects, outside this repo. Lessons
promoted there are removed from this file; Git history keeps them.

## 2026-10-23

- [new:2026-10-24] Check sustained throughput against freshness rules before expecting a full-source pass. Refreshing 9,276 distinct historical articles every 30 hours needs 7,420.8 fetches/day before index work, beyond the fixed 5,500 ceiling. D-112 explicitly separates fresh intake, fact processing and historical review; preserve old measurement definitions and every URL instead of manufacturing a green score.
- [new:2026-10-24] Embedding an entire prior seven-target plan in every new proof grows the plan sevenfold per batch and eventually blocks collection. Store each validated committed raw plan once under the existing lease and acknowledged escrow, then bind later proofs to its exact recorded content reference. Keep raw embedding only for legacy receipts without that reference.
- [new:2026-10-24] A manual collector is neither a successful nor failed scheduled attempt. Keep timer execution unmeasured with no invented denominator, while still enforcing its run, revision and coverage identities. A later release reconciliation time cannot renew the original source-check age.
- [new:2026-10-24] Manual publication verification consumes the same UTC-day gate and publication allowances as scheduled work. Reserve capacity for the upcoming scheduled cycle before dispatching another manual batch. Controlled rollback reuses accepted artifacts and does not consume another publication batch; never refund spent attempts to make a test fit.
- [new:2026-10-24] A correction's latest initial-admission time is not an expiry of its accepted historical fact. Replay accepted source evidence at its original admission time, retain publication dates and exact rows, and hold on a relevant policy/evidence change. Do not reintroduce a known bad frozen record because a new review is unavailable.
- [new:2026-10-24] A Vercel alias can report the expected application receipt before the detached receipt or static files converge. Rollback verification must retry the whole exact receipt pair and retained static inventory, with bounded attempts and unchanged criteria, and always restore the accepted current deployment. A historical exception type alone does not establish which check failed; retain safe phase/category diagnostics.
- [new:2026-10-24] The copied promotion hook invokes Node on the host by default, which cannot use the VM's Linux esbuild binary. Keep the hook enabled and route its Node invocation into OrbStack with translated paths. The actual complete fact guard must pass there before the deliberate PROMOTE=1 push; installing Mac dependencies or disabling the hook is unnecessary.
- [new:2026-10-23] Zero coverage credit does not excuse an unreserved source request. The read-only hosting canary must verify archived integrity without contacting market sources; actual diagnostics belong under the shared lease and fetch ledger. When a workflow change can start a job immediately, publish its matching code and workflow atomically through the existing GitHub connection, comparing the uploaded tree with the reviewed local tree.
- [new:2026-10-23] Font requests can hold a browser release check open after the application itself responds. Serving the exact existing font binaries and declarations locally removed that dependency without a timeout increase; retain licenses, source pins, offline font checks and same-data pixel comparisons. A source probe also needs the shared remote lease and acknowledged budget ceiling: a lock in one restored local copy cannot protect another runner's allowance.
- [new:2026-10-23] GitHub CLI OAuth scopes and an existing connected GitHub application's permissions can differ. The CLI lacked workflow write scope; the installed connection accepted the exact reviewed workflow on preview. Preserve the original local commits, rebase onto the actual updated preview and prove the complete tree is unchanged before pushing the remaining code. No new credentials or permission changes were needed.
- [new:2026-10-23] Decode bounded compression before article extraction, date/quote checks and correction reading while preserving raw evidence bytes. Bind the exact decoded model view into compressed-input cache identities and both partial/full replay; leave ordinary cache identities unchanged. A manual retained-body parser diagnostic does not prove a citation task used that parser: citation checks are transport-only.
- [new:2026-10-23] A parent filing index and a product's facts are different outputs. Use an explicit zero-fact issuer-index check for segment coverage and independently replay its source identity and complete retained index. Do not route a product through an issuer-level certification adapter. Actual SEC archive date ranges can enclose the rows rather than equal their extrema; require containment and exact row counts, with both declared and observed ranges retained.
- [new:2026-10-23] A listing is incomplete when its real continuation controls were ignored or its content lives behind an unfetched data endpoint. Decode bounded compression before classifying the body, isolate evidenced article cards from navigation, and retain missing-page and empty-shell failures. An advertised feed or a synthetic terminal layout cannot qualify an actual source.
- [new:2026-10-23] Re-run the actual audit command after moving source data; synthetic legacy fixtures can stay green while the real decoder breaks. Preserve the historical benchmark and verdicts, explicitly pin a migration to the new raw originals and baseline, and compare every relevant object. Historical source-file hashes must not be represented as hashes of refactored code or current corrected facts.
- [new:2026-10-23] Bind an accepted factual correction review to its own candidate, evidence, supplier identity and review rules. Binding every review to the entire source registry makes unrelated coverage repair invalidate historical proof. Keep the global inventory/build binding separate and require retained public correction rows, dates and admission metadata to remain exactly equal.
- [new:2026-10-23] Hashing an original data file does not bind the application's exported facts: code can override a field afterward. Independently reconstruct the expected projected views from fresh inputs and compare the actual supplier, event, evidence and original-history exports before building. Include every bound primary document in the correction history, even when a target's citation list omits a supplemental source.
- [new:2026-10-23] A publication-date check must cover crash recovery as well as ordinary promotion. A worker can die after the remote promotion crosses UTC midnight but before recording its acknowledgement. If recovery cannot prove timely first publication, restore the previously acknowledged deployment instead of silently accepting the old date.
- [new:2026-10-23] Correct the related evidence metadata with the fact. A drawer can repeat the same wrong date, qualifier or amount through a handwritten excerpt after its event is fixed. Verify replacement excerpts against actual source bytes, preserve the original record, and apply the corrected evidence view to every consumer. A publisher's paid-release disclosure supports its publication role only; a display-class correction must not grant financial-primary authority. Bind that narrow review scope separately and keep ordinary financial guards on immutable originals.
- [new:2026-10-23] Passing SEC/build checks do not establish support for hand-collected text. Pin a complete record inventory and check actual source bodies; distinguish directly contradicted readings from incomplete support or missing primary provenance. Keep known factual errors visible even when operational checks pass.
- [new:2026-10-23] A recorded URL and body hash cannot reconstruct a source after its temporary file disappears. Retain the original bytes and provenance when first checked. Recover unchanged temporary proof only against its already recorded hash; never give it a new retrieval time.
- [new:2026-10-23] A new daily event cannot safely correct an older same-date field or withdraw a duplicate. Preserve original history and bind a dated correction to the exact before-value, after-value or withdrawal, source evidence and current independent review. An assertion that all changed claims were verified does not audit arbitrary static edits.
- [new:2026-10-23] An exhausted retry must preserve same-day successful checks when their task, policy, evidence hashes and original source age still validate. Reconcile immutable prior receipts before reusing them; never renew their dates or refund the charged allowance. The archived replay retains 121 actual checks and the earlier 244-check counterfactual without new requests.
- [new:2026-10-23] Deployment rollback does not prove evidence continuity. Compare collector state with the publication candidate: retain every unresolved hold and quarantine older-policy facts with their full evidence. Close a hold only through an exact candidate/body match to a newly independently accepted fact; preserve a replayable resolution record.
- [new:2026-10-23] A source page's related-story sidebar can look like current event evidence. Scope extraction to the source's demonstrated article container, bind publication metadata to the exact observed canonical URL, and leave conflicting datelines unresolved. Preserve raw archived fixtures for regression tests.
- [new:2026-10-23] An actual timer can execute several hours after its cron window. Verify GitHub's schedule event and the matching immutable collection receipt; a delayed acceptance retry must preserve the original source-check time and budgets. Successful execution can reduce current coverage when rechecks exhaust the fetch allowance, so retain the new gaps rather than presenting the earlier count as fresh.
- [new:2026-10-23] A successful Vercel prebuilt upload does not prove that high-level promotion or rollback can resolve the same account. Use the explicit verified team and project API routes, validate the READY immutable target, await the live receipt, and recheck that automatic domain assignment stays closed. Runtime acceptance remains separate from local adapter tests.
- [new:2026-10-23] The public tracker export has no event inventory. Verify a missing event in the rendered feature and exact staged bundle; a rolling count can fall when an older event ages out even when the new correction is present.
- [new:2026-10-23] A GitHub concurrency group permits only one pending job, so a new pending callback can displace a collector even with cancel-in-progress false. Run read-only acceptance preflight outside the mutation group and require the actual scheduled collection receipt before requesting it.

## 2026-10-22

- [new:2026-10-22] Confirm a successful push and exact remote revision before dispatching a workflow. An early old-revision test was cancelled after reserving a conservative daily ceiling; the killed runner correctly retained that allowance. Recover only a GitHub-confirmed terminated lease, and never refund unknown model usage.
- [new:2026-10-22] A prebuilt preview is rebuilt when promoted through Vercel's preview-to-production path. Stage a production-target prebuilt artifact with no assigned domain, verify every static byte, then promote it. Use the dedicated rollback operation for a previously served deployment.
- [new:2026-10-22] A bounded run can finish while source coverage remains incomplete. Give execution and coverage separate outcomes and alerts; preserve every missing obligation and require the full SEC tier before publication. Prioritize mandatory SEC documents ahead of discretionary citation checks when capacity is scarce.

## 2026-10-18

- [new:2026-10-18] A scheduled workflow that has only ever run on its schedule is untested. `promote-certified.yml` failed every run for two days (a credential-free checkout of a private repo cannot `git fetch`), and nothing alerted because monitoring checked that the refresh ran, not that promotion succeeded. Put decision logic in a script with unit tests, and monitor each scheduled job's success and the end-to-end lag, not just that something ran.
- [new:2026-10-18] Machine-extracted text needs its own gate. The certification proved the numbers while an 8-K quote shipped as boilerplate. Every machine-written string now passes a validator before publish and in the data tests.

## 2026-10-16

- [new:2026-10-16] `pkill -f <pattern>` kills the shell that runs it when the pattern also appears in that shell's own command line (exit 144). Kill by PID, or use a pattern the command line cannot contain.
- [new:2026-10-16] GitHub scheduled workflows on a quiet repository start late and skip slots, especially the first runs after a schedule is added: the first `17 */4` refresh ran at 16:38, after two skipped slots. Alarm on "no run in N hours", never on a missed slot.
- [new:2026-10-16] Moving hundreds of documents is safe only with a mapping file and a script that rewrites both relative links and repo-root path mentions from that map; then check links before committing.
- [new:2026-10-16] A reviewer that has not seen the work finds label overclaims the author cannot see: "the event type is certified" read true to its author until a fresh agent showed the verifier never checks type per event.

## 2026-10-02

- [withheld:2026-10-02] A backgrounded tool call wrapping a command that ALSO backgrounds itself with a trailing `&` produces an orphaned, unreliable process; the wrapper returns immediately while the real work's survival across turns (especially across a session interruption) is uncertain. Pass the long-running command directly to the backgrounding mechanism without an internal `&`; that is the form that gives a trustworthy completion notification.
- [withheld:2026-10-02] After any session-rate-limit or similar interruption, a "completed exit code 0" notification for a background task is not proof it ran; check ground truth (a result file's timestamp/content, `ps aux`) before trusting it. One batch of this session's 74-supplier collector run silently never executed despite reporting success; only a timestamp check caught it.
- [withheld:2026-10-02] A supplier's own news counting as "unreadable" is only honest after a real fallback chain, not after one fetch failing; RSS/Atom, sitemap, an IR subdomain, a wire-service copy (GlobeNewswire/PR Newswire/Business Wire), and an EDGAR full-text search, in that order, with the failure detail naming which routes were tried.

- [withheld:2026-09-21] A build-time meaning gate (fiscal period vs. source, `verify-issue.ts`/`verify-prints.ts`) can't be satisfied by editing a locked, hashed issue or a corrected-in-place standing table. ## 2026-09-19

- [withheld:2026-09-19] Page composition accepted on a spec is not page composition anyone has seen. The weekly-issue front page passed three external review rounds, a full e2e suite and five build gates, and still nobody had looked at it at full page height until the promotion render: it opens with a chronological list of funding rounds down to a $60.0K pre-seed, with the judgment below four lanes. Render the whole page at both widths at the point the composition changes, not at the point it ships.

## 2026-08-27

- [withheld:2026-08-27] A purchase price allocation says what an acquirer thinks it bought. Two AI security deals put almost the whole price in goodwill and assigned nothing to customer relationships, while an adjacent deal in the same filing put $464M of $476M into customer relationships. That contrast is stronger evidence than any figure either company would state directly.

## 2026-10-23 · Source probes share collection's charged allowance

The former `onboard` command called its fetcher without a persistent reservation. Diagnostic
fetches still consume the same daily allowance. Require a store/contract/current-day-bound
reservation before every logical request, preserve failed-request charges, and keep probe results
unqualified with zero coverage credit. Tests use fictional fetchers and temporary state only.

- A publisher hostname does not establish editorial independence. The retained Yahoo Xage item
  identifies a paid GlobeNewswire release despite its original independent-source label. Preserve
  issuer, distributor and host roles separately; correct metadata through its dated review path.
- Valid HTML may contain valueless attributes. Normalize parser `None` values before class,
  relation or publication matching; replay the actual failing body and preserve its original hash.
