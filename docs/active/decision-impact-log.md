# Decision impact log

Prove the site changes real decisions — not just that we shipped code.

| Field | Value |
|---|---|
| **ID** | `SEC-MARKET-IMPACT-001` |
| **Goal** | Two logged uses in two weeks, against a pilot set named in advance (D-58) |
| **Success** | At least one entry where the read or tempo changed qualification, timing, or talk track |

---

## How to log an entry

Copy this block for each use:

```markdown
### YYYY-MM-DD — [role + segment + pseudonymous id, never a name]

- **Who:** (e.g. `account-team-A, West NorCal` or `client-3, financial services`. No names of ePlus
  personnel, accounts, or clients — the identifier mapping lives in the ePlus operating cockpit)
- **Looked at:** (e.g. Activity read, Cloud tempo, Fortinet print)
- **Source clicked:** (evidence ID or URL)
- **Decision or conversation change:** (one sentence — what was different?)
- **Did they already know it?** (U2 incremental value — no / partly / yes. "Yes" is a real result and
  must be recorded as readily as a win)
- **Were options still open?** (U3 lead time — had the decision already been made, or could this
  still change it?)
- **Market call changed?** No / Yes (if yes, escalate to owner)
```

The two middle questions exist because counting uses is not knowing whether this works. A reader who
acted on something they already believed, or who read it after the decision was made, is exposure
without value, and the log has to be able to say so.
