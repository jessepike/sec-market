## Work and acceptance

The owner clarified that the site has not yet helped with a real decision or conversation. Current
priority is making what is already present work consistently, durably, accurately and freshly;
coverage expansion and search follow. Reader value therefore remains unmeasured. Preserve the
declared gaps, but prioritize existing source operation and evidence continuity before adding
new source families.

1. Correct same-day retry waste. Reuse a hash-verified successful receipt only when its exact
   task, policy, source identity and source-specific age remain valid. Preserve original observation
   and verification times. Failed, changed-policy, new-day, expired or incomplete work must remain
   eligible for a real check. Prove that an exhausted retry cannot erase an otherwise valid success.
2. Remove provable duplicate source retrieval within a run while keeping independent source/task
   provenance, host rules, conditional-fetch chains and the full denominator. Do not share a
   response across incompatible source policies. Test both reuse and rejected reuse.
   For an already registered shared publisher, prioritize URLs that explicitly name the supplier
   within each existing current/audit bucket. Preserve every other URL and the existing document
   limits. URL priority is a scheduling hint; it cannot establish entity support or completeness.
3. Qualify missing/candidate source registrations using existing archived primary evidence first.
   A registration must identify the supplier, endpoint, scope, pagination/date boundaries and
   positive/quiet/blocked behavior. A corporate-wide sitemap cannot silently stand for every
   announcement about an individual supplier. Unsupported families stay incomplete.
4. Diagnose held claims individually. Repair extractors, dates or source bindings where evidence
   supports it. Re-run required independent review only inside the existing next-day allowance.
   List genuine source or judgment decisions for the owner separately from work agents can do.
   Resolve an old hold only with an explicit immutable link to an independently admitted current
   fact covering the exact candidate and source body. Keep the original held evidence and every
   unrelated hold. A later collector must not reopen a previously resolved identical hold.
5. Add a reproducible scorecard grounded in the intent's fresh, covered, used and reconstructable
   outcomes. Report durability, accuracy and reader value explicitly. Keep pass, fail and unmeasured
   distinct, attach exact evidence and denominators, and expose limitations. Do not blend unknown
   reader value or incomplete coverage into a flattering overall score.
6. Verify fixes against representative archived evidence and adversarial cases, then use the normal
   independent gate and actual scheduled collection/publication receipts when the allowance renews.
   Offline improvements are not proof of increased live coverage. Track outstanding work by cause,
   owner, next action and evidence rather than a growing list of raw URLs.

## Tracking surfaces

and evidence; its rendered Markdown companion is the human review surface. `status.md` points to
the latest actual receipt and scorecard. The GitHub coverage alert stays open until the measured
conditions recover. The goal remains active while required fixes, verification or genuine owner
inputs remain unresolved.

Reader value requires observed use or feedback. Until such evidence exists, it is unmeasured.
Existing technical tests do not estimate overall factual precision or eligible-event recall; a
fixed primary-source benchmark and explicit scoring denominators are required for those claims.
