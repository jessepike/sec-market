# Neutral SEC qualification diagnostic path

Status: implementation scope for offline development only, October 24, 2026. This does not authorize dispatch, source registration, qualification, or collection.

Add a narrow `sec_index` branch to the existing leased source-probe path. It handles only candidate source rows explicitly declared with the existing neutral SEC issuer fields and exact issuer submissions URL. It fetches the root and only the literal `CIK<CIK>-submissions-NNN.json` pages disclosed in that root whose declared date range intersects the existing 365-day lookback. Every request goes through the existing bound `PersistentProbeBudget` and `Fetcher`; each retained observation keeps the candidate `sourceId`, requested URL, original fetch time, and body reference. No cache entry from a parent or other source identity is accepted as a request result.

For a paired candidate `sec_documents` row, join it one-to-one with a candidate `sec_index` row by subject, ten-digit CIK, exact full issuer declaration, submissions URL, and lookback window. Validate candidate shape using existing source validators without promoting either registration. Use only the complete index root and literal older pages fetched in this same diagnostic to select every eligible primary URL by the existing filing-form allowlist and 365-day filing-date window. Fetch each selected primary body separately through the document source row, so the primary-document observation carries that document source ID. Apply the existing index-page bounds and the same durable shared daily fetch reservation; never truncate eligible body inventory. No parent source body or cache identity supplies a candidate primary observation. Keep the exact root/page/body URLs, filing dates, index observation references, and body observation references together in the diagnostic result.

Parse JSON as JSON, require the root CIK and exact legal name to match the candidate declaration, and retain the root's literal older-page declarations. Bind older flat SEC tables to the issuer through those exact CIK-bound filenames, validate their arrays, counts and declared date ranges, and reject conflicting accession rows across pages. Reject malformed, duplicate, wrong-issuer, unsafe, out-of-scope, or over-cap page declarations. Each primary body must be a fresh HTTP 200 at its exact selected URL, retain its source-bound observation, and pass the existing readable-document minimum before the body diagnostic can complete. This is a diagnostic: do not call the acceptance verifier with a copied `registration: verified`, change candidate registration, or emit qualification, facts, or source-check credit. Transported primary bodies establish neither semantic validation nor facts. An absent or failed response stays an explicit diagnostic failure.

Keep the committed market contract, source registry, seven-target qualification plan, source counts, required-task denominator, fetch/model budgets, and main-gate cap unchanged. The implementation adds parser/runtime support and offline tests only. Future integration and any real dispatch remain with the project owner.

Integration has two separate proof transitions. First, use the exact four-row proposal in [four-neutral-regulatory-bindings-spec-2026-10-24.md](four-neutral-regulatory-bindings-spec-2026-10-24.md) under `accuracy/` and add those unqualified SEC candidate rows to the contract. Review the coordinated contract hash, probe-plan binding, and correction outer-stamp replay before any fresh diagnostic request. This candidate addition does not widen or bypass the existing seven-target plan or its six corrections. Later, verified activation is a separate policy transition requiring its own exact contract and plan evidence; candidate diagnostics cannot stand in for that approval or evidence. Do not add a generic exception for policy-hash mismatch.
